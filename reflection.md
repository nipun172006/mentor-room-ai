# Reflection

When I started this assignment, I thought the main task would be writing three different descriptions. My first prompts were close to that, and the replies quickly showed the problem: all three bots sounded like the same helpful assistant. What worked better was giving each persona a different method. Anshuman’s prompt breaks a vague goal into something measurable. Abhimanyu’s prompt focuses more on routine, mentors, and a support system. Kshitij’s prompt starts with intuition and a small example before moving to the rule. The few-shot examples helped much more than simply adding words such as “friendly” or “motivational.”

GIGO was the clearest learning for me in this project. When the prompt only contained a name and a few adjectives, the output was generic. Once I added details from public talks, profiles, instructor pages, and student accounts, the answers became easier to tell apart. The output rules also made a noticeable difference. A short answer with one practical action and a follow-up question was more useful than a long motivational response. I learned that prompt engineering is not about finding one clever sentence. It is about giving the model enough context, examples, and boundaries to produce a repeatable result.

One part I had to be careful about was using real people as personas. The model can easily make up a personal story or quote if the prompt leaves room for it. I added a clear rule that these are classroom personas based on public information, not the real people. I also blocked invented placement claims, salary promises, and private opinions. This keeps the experience honest without removing the useful parts of their public teaching styles.

If I continued working on this, I would test the same set of questions with all three personas and ask a few Scaler students whether they can identify the intended mentor without seeing the name. I would use their feedback to rewrite examples that still overlap. On the product side, streaming replies and a simple thumbs-up/down button would be useful additions. For now, I kept the application focused on the assignment requirements: a clean chat screen, one small API route, three separate prompts, safe key handling, and proper mobile support.
